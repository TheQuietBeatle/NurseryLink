# Plan: Add Incident, Meal, and Supply History to Parent Child Dashboard

## Context

The parent child dashboard (`child_dashboard.tsx`) currently only shows temperature history. The header navigation already references `#incident_history`, `#meal_history`, and `#supply_history` anchors, but no content exists for these sections. The database has seed data for incidents (~50), meals (~3000), and supply requests (~35), but no backend API routes or React components exist for them.

## Changes

### 1. Add backend API routes (`backend/index.ts`)

Add three new GET endpoints:

- **`GET /incidents/:child_id`** — Query `incidient_report` joined with `incident_to_parent` and `account` (teacher name). Returns incident list for a child.
- **`GET /meals/:child_id`** — Query `activity_logs` filtered by `log_type = 'meal'` and `child_id`. The `log_details` JSONB has `food_portion` and `meal_type`. Join with `account` for teacher name.
- **`GET /supplies/:parent_id`** — Query `supply_request` joined with `supplyrequest_to_parent` and `teacher`/`account` for teacher name. Filter by parent_id.

### 2. Add TypeScript types (`NurseryLinkFront/src/lib/api.ts`)


### 3. Create `IncidentHistory` component (`NurseryLinkFront/src/components/parents/child/IncidentHistory.tsx`)

- Fetches from `GET /incidents/:child_id`
- Renders a list of incident cards with:
  - Severity badge (color-coded: green=low, amber=medium, orange=high, red=critical)
  - Description text
  - Teacher name and timestamp
  - Acknowledged/pending status indicator
- Card style follows the `record-card` pattern from the HTML mockup (left border stripe, clean card)
- Uses Tailwind classes from the project's design system (teal-*, paper, ink-soft, etc.)

### 4. Create `MealHistory` component (`NurseryLinkFront/src/components/parents/child/MealHistory.tsx`)

- Fetches from `GET /meals/:child_id`
- Renders a timeline-style list of meal entries (inspired by `parent_daily_feed` HTML mockup)
- Each entry shows:
  - Meal type icon (fork/knife for breakfast, plate for lunch, cookie for snack)
  - Meal type label and timestamp
  - Food portion badge (Full/Half/Small)
  - Comments/description
- Color-coded left stripe (teal for meals)

### 5. Create `SupplyHistory` component (`NurseryLinkFront/src/components/parents/child/SupplyHistory.tsx`)

- Fetches from `GET /supplies/:parent_id`
- Renders a list of supply request cards with:
  - Item name and quantity
  - Status badge (pending=amber, approved=blue, fulfilled=green, cancelled=gray)
  - Teacher name and request timestamp
  - Note if present
  - Fulfilled timestamp if fulfilled

### 6. Update `ChildDashboard` (`NurseryLinkFront/src/components/parents/child/child_dashboard.tsx`)

- Import the three new components
- Add `<section id="incident_history">`, `<section id="meal_history">`, `<section id="supply_history">` after the temperature section
- Pass `child.id` to incident and meal components
- Pass parent account ID (from `account.id`) to supply component — need to resolve parent_id from account_id

### 7. Add parent_id resolution

The supply endpoint needs `parent_id`, but the dashboard only has `account.id`. Add a helper or a small backend endpoint `GET /parent/account/:account_id` to resolve `parent_id` from `account_id`. Alternatively, query supply requests by joining through `parent.account_id` on the backend.

**Decision**: Update the supply query to accept `account_id` instead and join through the `parent` table on the backend.
